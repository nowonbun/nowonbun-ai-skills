# Coding Assistant

# Must

## Scope
- 이 스킬은 코드, 구성 또는 실행 동작에 영향을 주는 개발자 문서를 생성·수정·검토할 때 적용해야 합니다.
- 읽기 전용 진단이나 해결책 비교만 필요한 작업은 engineer의 범위로 처리해야 합니다.

## Source of Truth
- 이 문서는 `./SKILL.md`에 있는 코딩 변경 조정, 변경 위험 프레임워크, 로컬 검증 계획 및 결과 보고 구조를 규정합니다.
- 이 문서는 외부 교차 검토 런타임, 외부 검토 로그 스키마 또는 일반적인 스킬 문서 형식 규칙을 규정하지 않습니다.
- 외부 검토는 사용자가 명시적으로 요청한 경우에만 해당 검토 도구의 전용 스킬 또는 운영 규칙을 참조해야 합니다.

## Change Classification Rules
- 구현 전에 각 요청을 비파괴적 또는 파괴적 변경으로 분류해야 합니다.
- 스키마 변경, API 계약 변경, 인증 또는 권한 변경, 대규모 삭제 및 워크플로를 방해하는 구성 변경은 파괴적 변경으로 처리해야 합니다.
- 분류에 따른 승인 요구 사항을 문서화해야 합니다.

## Execution
- 사용자 요청, 저장소 증거 및 대상 경로로 변경 범위를 정해야 합니다.
- 명시적으로 요청된 범위 안의 되돌릴 수 있는 로컬 편집과 비파괴 검증은 추가 승인 없이 수행해야 합니다.
- 외부 쓰기, 데이터 손실 가능 작업, 권한·자격 증명 변경, 배포 또는 범위의 실질적 확대에는 실행 전 확인을 받아야 합니다.
- 현재 요청이 대상과 영향을 이미 명확히 승인했다면 같은 승인을 반복해서 요구해서는 안 됩니다.
- 변경은 목적을 달성하는 최소 범위로 제한해야 합니다.
- 코드, 문서 또는 구성 쓰기를 포함하는 작업은 변경 목적, 대상 파일 및 검증 방법이 확인된 후에만 Edit/Write 도구 또는 기타 쓰기 도구를 실행해야 합니다.

## Verification
- 결함 수정과 동작 변경에는 관찰 가능한 테스트 또는 동등한 검증을 선택해야 합니다.
- 문서·형식·참조 변경에는 정적 검사로 충분한지 판단해야 합니다.
- 실행한 검증과 실패·미실행 항목을 구분해 보고해야 합니다.
- 외부 AI 검토를 기본 완료 조건으로 사용해서는 안 됩니다.
- 사용자 또는 저장소 규칙이 외부 검토를 필수로 지정한 경우 외부 검토 완료 전까지 완료 상태를 보고해서는 안 됩니다.

## Reporting
- 변경 파일, 핵심 결과, 검증 결과와 남은 위험을 보고해야 합니다.
- 확인하지 못한 결과는 검증되지 않음으로 표시해야 합니다.
- 외부 검토가 사용자 또는 저장소 규칙에 의해 요구되었는지 여부와 실행 결과를 보고해야 합니다.

# Must NOT

## Scope and Safety
- 요청 범위 밖의 파일을 함께 정리해서는 안 됩니다.
- 안전한 로컬 변경을 형식적인 계획 승인이나 외부 검토 대기로 차단해서는 안 됩니다.
- 검증 실패나 미실행 상태를 숨겨서는 안 됩니다.
- 계획만 존재하는 상태를 완료로 보고해서는 안 됩니다.
- 파괴적이거나 외부 상태를 바꾸는 작업을 승인 없이 실행해서는 안 됩니다.
- 사용자 또는 저장소 규칙이 외부 검토를 필수로 지정하지 않았는데도 외부 검토를 기본 관문으로 설정해서는 안 됩니다.

# Flow

1. 요청을 비파괴적 또는 파괴적 요청으로 분류하고 대상 범위를 확인합니다.
2. 쓰기 작업이 포함되는 경우 변경 목적, 대상 파일 및 검증 방법을 확정합니다.
3. 파괴적 변경이면 사용자 승인을 받은 뒤 변경을 실행하고, 비파괴적 변경이면 확정된 범위 안에서 바로 실행합니다.
4. 변경 위험에 맞는 검증을 실행하거나 미실행 사유를 기록합니다.
5. 외부 검토가 필수로 지정된 경우 외부 검토 결과를 확보하거나 차단 상태를 보고합니다.
6. 변경된 파일, 검증 증거, 외부 검토 요구 여부 및 잔여 위험을 보고합니다.

# Definition of Done

## Verification
- 요청 범위 안의 변경만 존재합니다.
- 변경 분류 및 승인 요구 사항이 문서화되어 있습니다.
- 검증 깊이가 변경 위험에 비례합니다.
- 안전한 로컬 작업은 불필요한 승인 없이 완료됩니다.
- 외부·파괴적 작업의 확인 경계가 유지됩니다.
- 외부 검토가 필수인지 여부와 실행 결과 또는 차단 상태가 기록됩니다.

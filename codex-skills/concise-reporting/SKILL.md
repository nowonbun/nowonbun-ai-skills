# Concise Reporting

# Must

## Scope
- 이 스킬은 완료, 상태, 실패, 검증 또는 결정 요청을 사용자에게 보고할 때 적용해야 합니다.
- 작업 수행 방식이나 검증 명령 자체는 이 스킬에서 규정하지 않습니다.

## Reporting
- 첫 문장에 결론을 배치해야 합니다.
- 기본 보고에는 변경 또는 발견, 검증 결과와 사용자의 결정에 영향을 주는 남은 위험만 포함해야 합니다.
- 실패 보고에는 실패 지점, 증거 및 다음 행동을 포함해야 합니다.
- 중지 요청에는 차단 사유, 필요한 결정 및 선택지별 영향을 포함해야 합니다.
- 상세 설명을 요청받았거나 복수의 독립 발견이 있으면 제목과 불릿으로 구조화할 수 있습니다.
- 파일을 언급할 때는 사용자가 찾을 수 있는 경로와 필요한 경우 줄 번호를 제공해야 합니다.
- 확인하지 않은 내용은 검증되지 않음으로 표시해야 합니다.

# Must NOT

## Noise
- 같은 결론을 여러 표현으로 반복해서는 안 됩니다.
- 내부 준비 단계, 스킬 선택 과정 또는 사용자 결정에 영향이 없는 세부사항을 나열해서는 안 됩니다.
- 줄 수 제한 때문에 필수 증거, 실패 또는 남은 위험을 생략해서는 안 됩니다.
- 모든 응답에 고정된 불릿 수나 줄 수를 강제해서는 안 됩니다.
- 증거 없이 완료를 선언해서는 안 됩니다.

# Flow

1. 결론과 사용자가 알아야 할 결과를 선택합니다.
2. 결과를 뒷받침하는 최소 증거를 연결합니다.
3. 남은 위험 또는 다음 결정이 있을 때만 추가합니다.
4. 중복과 내부 절차를 제거합니다.

# Definition of Done

## Verification
- 결론이 먼저 제시됩니다.
- 검증 결과와 필요한 예외가 보존됩니다.
- 보고 길이는 작업 복잡도에 비례합니다.
- 반복과 내부 절차가 제거됩니다.

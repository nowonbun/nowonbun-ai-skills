# Markdown Safe Writing

# Must

## Scope
- 이 스킬은 Windows에서 한국어 또는 비 ASCII 문자가 포함된 텍스트 문서를 생성·수정하거나 인코딩 손상을 조사할 때 적용해야 합니다.
- ASCII 전용 파일을 안전한 편집 도구로 소규모 수정하는 작업에는 추가 절차를 요구해서는 안 됩니다.

## Writing
- 기존 파일을 수정할 때는 부분 패치를 우선해야 합니다.
- 전체 파일을 생성하거나 다시 쓸 때는 UTF-8 인코딩을 명시할 수 있는 API를 사용해야 합니다.
- 셸 인용이나 코드 페이지로 비 ASCII 본문이 손상될 가능성이 있으면 apply_patch 또는 UTF-8을 명시한 파일 API를 사용해야 합니다.
- 대상 경로와 수정 범위를 쓰기 전에 확인해야 합니다.

## Verification
- 쓰기 후 파일을 UTF-8 strict 모드로 다시 읽어야 합니다.
- 다른 검사에서 최종 파일의 같은 UTF-8·문자 보존 검사를 완료했다면 `../runtime-management_work-runtime/SKILL.md`의 증거 재사용 조건을 적용해야 합니다.
- U+FFFD, 비정상적인 물음표 반복 및 대표 한국어 문장의 손실 여부를 확인해야 합니다.
- 콘솔 표시가 깨져 보이면 파일 바이트 또는 UTF-8 디코딩 결과와 구분해야 합니다.
- 손상이 확인되면 추가 덮어쓰기를 중지하고 검증된 원본이나 버전 관리 상태에서 복구해야 합니다.

# Must NOT

## Unsafe Text Handling
- 인코딩을 알 수 없는 기본 쓰기 동작으로 한국어 문서를 덮어써서는 안 됩니다.
- 콘솔 표시만으로 파일 손상을 단정해서는 안 됩니다.
- UTF-8 디코딩 성공만 확인하고 대체 문자나 본문 손실 검사를 생략해서는 안 됩니다.
- 인코딩 검증을 위해 외부 AI 검토나 별도 이력 문서를 요구해서는 안 됩니다.
- 손상된 본문 위에 추측한 텍스트를 부분 덮어써서는 안 됩니다.

# Flow

1. 대상 경로와 기존 인코딩 상태를 확인합니다.
2. 비 ASCII 본문을 보존하는 쓰기 방법으로 최소 변경합니다.
3. UTF-8 디코딩과 대표 문자 보존을 검사합니다.
4. 손상이 있으면 복구하고, 없으면 변경과 검증 결과를 보고합니다.

# Definition of Done

## Verification
- 수정 파일은 UTF-8 strict 디코딩을 통과합니다.
- 대표 한국어와 비 ASCII 문자가 보존됩니다.
- 콘솔 표시 문제와 파일 손상이 구분됩니다.

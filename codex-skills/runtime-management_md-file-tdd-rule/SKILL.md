# Markdown File TDD Rule

# Must

## Scope
- 이 스킬은 규칙, 계약, 링크 구조 또는 소비자 동작을 바꾸는 Markdown·텍스트 변경에 적용해야 합니다.
- 오탈자, 표현 정리, 줄바꿈 및 의미를 바꾸지 않는 소규모 편집에는 전체 TDD 절차를 요구해서는 안 됩니다.

## Validation
- 의미 변경 전에는 유지할 계약과 변경할 결과를 식별해야 합니다.
- 링크·경로 변경에는 대상 존재와 깨진 참조 검사를 포함해야 합니다.
- 구조 변경에는 제목 계층, 필수 섹션 및 코드 블록 경계를 검사해야 합니다.
- 규칙 변경에는 상위 문서와의 충돌, 중복 소유권 및 실행 가능성을 확인해야 합니다.
- 한국어 문서는 UTF-8 디코딩과 대표 문자의 보존 여부를 확인해야 합니다.
- 반복 회귀나 자동 검증 가치가 있는 계약에만 지속 테스트를 추가해야 합니다.

# Must NOT

## Over-Testing
- 모든 문서 변경에 실패 테스트, 승인 기준 문서, 변경 식별자 또는 정기 품질 검토를 요구해서는 안 됩니다.
- 렌더링이 필요 없는 규칙 문서에 시각 검증을 강제해서는 안 됩니다.
- 검증 비용이 변경 위험보다 큰 경우 불필요한 테스트 계층을 추가해서는 안 됩니다.
- 근거 없는 사실을 검증된 내용으로 작성해서는 안 됩니다.

# Flow

1. 변경이 의미·계약·참조에 미치는 영향을 확인합니다.
2. 영향을 관찰할 수 있는 최소 검증을 선택합니다.
3. 변경 후 대상 계약과 관련 참조를 검사합니다.
4. 실패가 있으면 원인과 남은 위험을 보고합니다.

# Definition of Done

## Verification
- 검증 깊이가 문서 변경 위험에 비례합니다.
- 의미·참조·구조·UTF-8 중 해당하는 항목만 확인합니다.
- 소규모 편집이 불필요한 TDD 절차로 차단되지 않습니다.

# Work Runtime

# Must

## Scope
- 이 스킬은 AGENTS.md가 위임한 공통 런타임 제어에만 적용해야 합니다.
- 읽기·평가·진단 작업은 관련 자료를 확인하고 결과를 보고하는 범위에서 별도 승인 없이 진행해야 합니다.
- 쓰기 작업은 사용자 요청 범위, 대상 경로 및 검증 방법을 확인한 뒤 진행해야 합니다.

## Shared Controls
- 정확한 트리거 워크플로는 전체 입력이 트리거 문구와 일치할 때만 실행해야 합니다.
- 동일한 정확한 트리거가 둘 이상 활성화되면 실행을 중지하고 충돌을 보고해야 합니다.
- 경로 기반 작업은 대상이 관리 폴더 안의 하나의 정규 경로로 확인되어야 합니다.
- 외부 쓰기, 파괴적 작업, 구매 또는 요청 범위의 실질적 확대에는 실행 전 사용자 확인이 필요합니다.
- 요청된 범위 안의 되돌릴 수 있는 로컬 편집과 비파괴 검증은 별도 승인 없이 진행해야 합니다.

## Validation
- 변경 작업은 대상 파일, 변경 목적 및 결과 확인 방법을 실행 전에 식별해야 합니다.
- 결함 수정이나 동작 변경에는 실패를 재현하거나 변경 결과를 관찰할 수 있는 검증을 우선해야 합니다.
- 문구·형식·참조 정리에는 변경 범위에 맞는 정적 검사만으로 검증할 수 있습니다.
- 같은 실행 안에서는 대상·관련 의존 파일의 해시, 검사 규칙·도구 버전 및 검사 범위가 모두 동일한 성공 증거를 재사용해야 합니다. 하나라도 달라지거나 이전 증거가 없으면 영향받은 검사를 다시 실행해야 합니다.
- 참조 존재 검사는 대상의 현재 존재·경로를 다시 확인한 경우에만 재사용할 수 있습니다. 권한, 원격 상태 및 시간 의존 데이터는 로컬 파일 해시만으로 재사용해서는 안 됩니다.
- 여러 스킬이 같은 검사를 요구하면 한 번의 결과를 공유하되, 마지막 수정 이후의 파일 상태를 검증해야 합니다. 재사용은 해당 증거가 확인한 항목에만 적용하며 별도 캐시·이력 파일을 의무화하지 않습니다.
- MCP 호출은 해당 호출에 필요한 ID, URL 또는 대상 참조가 있을 때만 그 값을 사전 검증해야 합니다.
- MCP 쓰기 후에는 대상 ID, 결과, 실패 사유 및 재실행 필요성을 보고해야 합니다.

## Stop Conditions
- 작업 완료에 필수인 입력이 누락되거나 결과에 실질적인 차이를 만드는 모호성이 남으면 실행을 중지해야 합니다.
- 활성 규칙 충돌을 우선순위 모델로 해결할 수 없으면 실행을 중지해야 합니다.
- 쓰기 대상이 하나의 정규 경로로 확인되지 않거나 요청 범위를 벗어나면 실행을 중지해야 합니다.
- 선택적 자료나 보조 도구가 없다는 이유만으로 안전한 로컬 작업을 중지해서는 안 됩니다.

## Reporting and Encoding
- 결과 보고는 결론, 변경 또는 발견, 검증 결과, 남은 위험만 포함해야 합니다.
- 같은 목적의 연속 도구 조회는 실행 전 목적을 한 번 설명하고 최종 결과에 통합해야 합니다. 대상·목적 변경, 승인 요청, 실패 및 사용자 결정이 필요한 예외는 즉시 알려야 합니다.
- 실패 보고는 원인, 증거 및 재실행 조건을 포함해야 합니다.
- 중지 요청은 차단 사유, 필요한 결정 및 선택지별 영향을 포함해야 합니다.
- 텍스트 문서는 UTF-8로 저장하고, 쓰기 후 UTF-8 디코딩과 대표 비 ASCII 문자의 보존 여부를 확인해야 합니다.

# Must NOT

## Over-Control
- 모든 작업에 동일한 다단계 계획·검토·보고 절차를 강제해서는 안 됩니다.
- 사용자 요청이 없는 외부 AI 검토나 AI 간 위임을 완료 조건으로 사용해서는 안 됩니다.
- 안전한 로컬 읽기, 편집 또는 검증을 형식적인 승인 대기로 차단해서는 안 됩니다.
- 상위 문서가 소유한 안전 경계나 개별 도구 스킬의 매개변수 규칙을 복제해서는 안 됩니다.

# Flow

1. 요청 유형과 대상 범위를 확인합니다.
2. 필요한 스킬과 증거만 선택합니다.
3. 작업 위험에 비례하는 검증 방법을 정하고 범위 안에서 실행합니다.
4. 실행 결과를 검증하고 결론과 남은 위험을 보고합니다.

# Definition of Done

## Verification
- 읽기 작업, 안전한 로컬 변경 및 외부·파괴적 작업의 승인 경계가 구분됩니다.
- 검증 깊이는 작업 위험과 관찰 가능한 영향에 비례합니다.
- 외부 AI 검토 없이 로컬 증거로 완료할 수 있습니다.
- UTF-8 검증과 필수 실패·중지 보고 필드가 유지됩니다.

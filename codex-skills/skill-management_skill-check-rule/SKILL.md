# Skill Check Rule

# Must

## Scope
- 이 스킬은 활성 SKILL.md, `global_instructions.md`, `AGENTS.md`, 루트 `README.md`, 추적 중인 수동 검토 프로필 및 직접 연결된 거버넌스·검증 문서의 일관성을 감사할 때 적용해야 합니다.
- 백업, 이력, 예시, 비활성 테스트 및 `**/.claude/worktrees/**` 복제본은 활성 규칙과 분리해서 평가해야 합니다.

## Checks
- 각 활성 스킬의 정규 경로, UTF-8 디코딩, frontmatter name·description 및 필수 H1을 확인해야 합니다.
- 루트 README와 운영 설명 문서가 추적 중인 파일의 실제 존재 여부와 역할을 정확히 설명하는지 확인해야 합니다.
- 운영 참조는 실제 대상의 존재와 참조 방향을 확인해야 합니다.
- 제거된 구성 요소가 활성 저장소 지도, 테스트 또는 운영 문서에 남아 있지 않은지 확인해야 합니다.
- 같은 조건에서 동시에 만족할 수 없는 규칙은 충돌로 보고해야 합니다.
- 동일한 결정을 여러 문서가 소유하거나 필수 절차가 순환하면 중복 또는 순환 의존으로 보고해야 합니다.
- 검증할 증거가 없는 항목은 통과가 아닌 검증되지 않음으로 표시해야 합니다.
- 테스트 문서는 실행 동작, 고위험 계약 또는 반복 회귀를 검증할 가치가 있을 때만 요구해야 합니다.

## Reporting
- 발견은 blocking, high, medium, low 순서로 분류해야 합니다.
- 보고서는 결론, 근거 파일·줄 또는 실행 로그, 영향 및 권장 조치를 포함해야 합니다.
- 형식 선호만 위반하고 실행 의미에 영향이 없으면 차단 오류로 분류해서는 안 됩니다.

# Must NOT

## Evaluation Boundaries
- 백업이나 이력을 활성 규칙으로 집계해서는 안 됩니다.
- 존재하지 않는 공통 템플릿을 모든 스킬에 강제해서는 안 됩니다.
- 외부 검토 또는 이력 기록이 없다는 이유만으로 로컬 스킬을 실패 처리해서는 안 됩니다.
- 참조 순환만으로 실행 불가능성을 단정해서는 안 되며 실제 의무 흐름을 확인해야 합니다.
- 증거 없이 성공 또는 실패를 단정해서는 안 됩니다.

# Flow

1. 헌법 문서, 저장소 지도, 수동 검토 프로필 및 활성 스킬 목록의 정규 경로를 수집합니다.
2. `**/.claude/worktrees/**`와 백업·이력 복제본을 활성 검사 집합에서 제외합니다.
3. 구조, UTF-8, identity, 문서 역할과 직접 참조를 검사합니다.
4. 충돌, 중복 소유권 및 실행 불가능한 순환을 검사합니다.
5. 필요한 테스트 또는 검증 증거를 확인하고 심각도 순서로 보고합니다.

# Definition of Done

## Verification
- 활성·비활성 문서가 분리됩니다.
- 루트 저장소 지도와 실제 추적 파일의 존재·역할이 일치합니다.
- 구조, 참조, 충돌 및 인코딩 결과에 증거가 연결됩니다.
- 테스트 요구는 위험이나 회귀 근거가 있는 스킬에만 적용됩니다.
- 검증되지 않은 항목이 성공으로 처리되지 않습니다.

# Skill Check Rule

# Must

## Scope
- 이 스킬은 요청된 활성 스킬과 직접 관련된 구성·참조·검증 문서의 일관성을 감사할 때 적용해야 합니다.
- 백업, 이력, 예시, 비활성 테스트 및 `**/.claude/worktrees/**` 복제본은 활성 규칙과 분리해서 평가해야 합니다.
- 기본 검사는 대상·변경 파일, 직접 참조와 적용되는 상위 규칙으로 제한해야 합니다. 전체 감사는 사용자의 명시적 요청이나 공통 규칙 변경으로 수행하고, 후자는 해당 규칙의 소비자 전체를 검사해야 합니다.
- 루트 README는 전체 저장소 감사 또는 저장소 지도 변경 시 확인해야 합니다. 사용자 직접 실행용 다른 모델 검토 프로필은 명시적으로 검토를 요청받지 않으면 수집하거나 완료 조건에 포함해서는 안 됩니다.

## Checks
- 각 활성 스킬의 정규 경로, UTF-8 디코딩, frontmatter name·description 및 필수 H1을 확인해야 합니다.
- 검사 범위에 포함된 저장소 지도와 운영 문서가 파일의 실제 존재 여부와 역할을 정확히 설명하는지 확인해야 합니다.
- 운영 참조는 실제 대상의 존재와 참조 방향을 확인해야 합니다.
- 제거된 구성 요소가 활성 저장소 지도, 테스트 또는 운영 문서에 남아 있지 않은지 확인해야 합니다.
- 같은 조건에서 동시에 만족할 수 없는 규칙은 충돌로 보고해야 합니다.
- 동일한 결정을 여러 문서가 소유하거나 필수 절차가 순환하면 중복 또는 순환 의존으로 보고해야 합니다.
- 검증할 증거가 없는 항목은 통과가 아닌 검증되지 않음으로 표시해야 합니다.
- 테스트 문서는 실행 동작, 고위험 계약 또는 반복 회귀를 검증할 가치가 있을 때만 요구해야 합니다.
- 정형 검사는 `./scripts/validate-skills.ps1`로 일괄 실행하고 모델은 실패 항목·필요한 주변 문장과 의미 검토 대상만 읽어야 합니다. 실행 방법과 한계는 `./README.md`를 참조합니다. 스크립트를 실행할 수 없으면 같은 범위의 로컬 정적 검사로 대체하고 미검증 항목을 밝혀야 합니다.
- 증거 재사용은 `../runtime-management_work-runtime/SKILL.md`를 따라야 하며, 변경분 검사를 전체 감사 통과로 보고해서는 안 됩니다.

## Reporting
- 발견은 blocking, high, medium, low 순서로 분류해야 합니다.
- 보고서는 결론, 근거 파일·줄 또는 실행 로그, 영향 및 권장 조치를 포함해야 합니다.
- 형식 선호만 위반하고 실행 의미에 영향이 없으면 차단 오류로 분류해서는 안 됩니다.

# Must NOT

## Evaluation Boundaries
- 백업이나 이력을 활성 규칙으로 집계해서는 안 됩니다.
- 존재하지 않는 공통 템플릿을 모든 스킬에 강제해서는 안 됩니다.
- 외부 검토 또는 이력 기록이 없다는 이유만으로 로컬 스킬을 실패 처리해서는 안 됩니다.
- 참조 순환만으로 실행 불가능성을 단정해서는 안 되며 실제 의무 흐름을 확인해야 합니다.
- 증거 없이 성공 또는 실패를 단정해서는 안 됩니다.

# Flow

1. 기본 검사 또는 전체 감사 범위를 정하고 실제 대상 목록을 확정합니다.
2. 재사용 가능한 증거를 확인하고 나머지 정형 검사를 일괄 실행합니다.
3. 실패 주변 문장과 의미 변경을 읽어 충돌·소유권·실행 가능성을 검토합니다.
4. 검사 범위, 신규·재사용 증거, 미검증 항목과 발견을 보고합니다.

# Definition of Done

## Verification
- 활성·비활성 문서가 분리됩니다.
- 검사한 파일 목록과 제외 범위를 확인할 수 있습니다.
- 구조, 참조, 충돌 및 인코딩 결과에 증거가 연결됩니다.
- 테스트 요구는 위험이나 회귀 근거가 있는 스킬에만 적용됩니다.
- 검증되지 않은 항목이 성공으로 처리되지 않습니다.

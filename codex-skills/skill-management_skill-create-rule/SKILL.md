# Skill Create Rule

# Must

## Scope
- 이 스킬은 SKILL.md를 생성하거나 수정할 때 적용해야 합니다.
- 형식보다 스킬의 선택 조건, 행동 경계 및 검증 가능성을 우선해야 합니다.

## Structure
- 파일 맨 위의 YAML frontmatter에는 name과 description만 포함해야 합니다.
- name은 소문자, 숫자와 하이픈으로 구성된 64자 이하 식별자여야 합니다.
- description은 사용 시점과 수행 목적을 한 문장의 한국어로 설명해야 합니다.
- 본문에는 문서 제목, Must, Must NOT, Definition of Done을 포함해야 합니다.
- 순서가 결과에 영향을 줄 때만 Flow를 포함해야 합니다.
- 각 규칙은 조건과 하나의 행동을 식별할 수 있어야 합니다.

## Content
- Scope는 이 스킬을 선택할 조건과 선택하지 않을 조건을 구분해야 합니다.
- Source of Truth가 필요하면 현재 문서가 소유하는 결정과 외부 문서가 소유하는 결정을 구분해야 합니다.
- 다른 스킬은 본문에서 frontmatter name으로 지칭할 수 있으며, 파일 존재 검증이 필요한 경우 실제 상대 경로를 함께 사용할 수 있습니다.
- 오류 처리와 중지 조건은 실제 실패 비용이 있거나 안전 경계가 필요한 경우에만 정의해야 합니다.
- 예시, 다이어그램, README 및 모니터링 섹션은 사용자 요청 또는 이해·운영에 필요한 근거가 있을 때만 추가해야 합니다.
- 기존 스킬을 수정할 때는 요청 범위 안에서 최소 변경하고 관찰 가능한 동작을 검증해야 합니다.

# Must NOT

## Over-Specification
- 동일한 규칙을 Must, Flow 및 Definition of Done에 문장 그대로 반복해서는 안 됩니다.
- 모든 스킬에 승인, 이력, 외부 검토, 다이어그램, README 또는 테스트 문서를 일률적으로 요구해서는 안 됩니다.
- 설명만으로 충분한 단순 스킬에 운영 모니터링이나 복구 절차를 추가해서는 안 됩니다.
- 상위 문서의 전역 안전 규칙과 응답 원칙을 복제해서는 안 됩니다.
- 서로 충돌하는 언어, 경로 또는 형식 요구 사항을 정의해서는 안 됩니다.

# Flow

1. 적용 조건과 비적용 조건을 정의합니다.
2. 필요한 행동, 금지 행동 및 검증 기준만 작성합니다.
3. 중복, 모호성, 깨진 참조 및 과잉 절차를 검사합니다.
4. UTF-8과 frontmatter 구조를 확인합니다.

# Definition of Done

## Verification
- 선택 조건이 구체적이며 다른 스킬과의 경계가 설명됩니다.
- 필수 구조와 frontmatter가 유효합니다.
- 규칙이 중복되거나 서로 충돌하지 않습니다.
- 보조 문서와 절차는 필요성이 확인된 경우에만 존재합니다.

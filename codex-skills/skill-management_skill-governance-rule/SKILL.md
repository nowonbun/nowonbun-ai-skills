# Skill Governance Rule

# Must

## Scope
- 이 스킬은 승인, 중지, 롤백 또는 외부 상태 변경 규칙을 설계하거나 검토할 때 적용해야 합니다.
- 문서 형식과 일반 작업 절차는 이 스킬의 범위가 아닙니다.

## Risk Tiers
- 거버넌스 계층은 baseline과 strict로 구분해야 합니다.
- 로컬 읽기, 분석, 요청 범위 안의 되돌릴 수 있는 편집과 비파괴 검증에는 baseline을 적용해야 합니다.
- 외부 쓰기, 데이터 삭제·초기화, 권한·자격 증명 변경, 결제, 배포 또는 즉시 복구하기 어려운 공유 상태 변경에는 strict를 적용해야 합니다.

## Baseline Controls
- baseline은 명확한 실행 범위, 결과 확인 및 실패 보고만 요구해야 합니다.
- 사용자가 요청한 안전한 로컬 변경에는 추가 승인이나 다단계 검토를 요구해서는 안 됩니다.

## Strict Controls
- strict는 승인 주체, 실행 전 확인 조건, 실패 시 중지 조건 및 가능한 복구 방법을 정의해야 합니다.
- 재시도가 부작용을 중복시킬 수 있으면 중복 방지 키나 재시도 제한을 정의해야 합니다.
- 사용자의 현재 요청이 대상과 영향을 명확히 승인한 경우 동일 범위의 승인을 다시 요구해서는 안 됩니다.

# Must NOT

## Over-Governance
- 위험 근거 없이 strict를 선택해서는 안 됩니다.
- 외부 AI 검토, 이력 문서 또는 별도 승인자를 모든 스킬의 완료 조건으로 요구해서는 안 됩니다.
- 안전한 로컬 검증을 공유 상태 변경과 동일하게 취급해서는 안 됩니다.
- 형식 규칙이나 보고 문구를 이 스킬에서 재정의해서는 안 됩니다.

# Flow

1. 작업이 변경하는 상태와 복구 가능성을 확인합니다.
2. strict 조건이 있으면 해당 위험에 필요한 제어만 추가합니다.
3. strict 조건이 없으면 baseline으로 실행합니다.
4. 결과와 남은 위험을 검증합니다.

# Definition of Done

## Verification
- baseline과 strict의 선택 기준이 상태 영향과 복구 가능성으로 구분됩니다.
- 안전한 로컬 작업은 불필요한 승인 없이 진행할 수 있습니다.
- strict 제어는 확인된 위험에만 연결됩니다.
